# 진짜최종.zip — 규칙·예시 파일·QA

기준은 `CLAUDE.md`(기능·판정 규칙·결정 사항)와 `DESIGN.md`(화면)다. `docs/spec.md`는 참고 문서이고 다르면 CLAUDE.md를 따른다.
이 스킬은 규칙을 새로 정하지 않는다. 두 문서에 없는 것은 "확인 필요"로 적고, 문서와 다른 동작을 찾으면 멈추고 알린다.

## 무엇을 할지 고르기
요청에 맞는 절 하나만 한다. "QA 해줘"처럼 범위가 없으면 4절 전체 QA.

| 요청 | 할 일 |
|---|---|
| 규칙 보여줘 · 키워드/점수/날짜 표기 바꿔줘 | 1절 규칙 |
| 예시 파일 만들어줘 · 날짜 맞춰줘 | 2절 예시 파일 (`/make-samples`) |
| 기능 하나 고친 직후 · 결과 확인 | 3절 빠른 확인 (`/check-result`) |
| QA · 테스트 · 배포 전 점검 | 4절 전체 QA |

| 명령 | 파일 | 하는 일 |
|---|---|---|
| `npm run samples` | `scripts/make-samples.ts` | `manifest.json`의 demo·edge 파일을 만들고 수정 날짜를 맞춤. 같은 입력이면 같은 바이트 |
| `npm run check` | `scripts/check-result.ts` | demo·edge 파일로 분석·이름 변경 결과를 `expected.json`과 비교 |
| `npm run qa` | `scripts/qa.ts` | 규칙 + 단위(기본 이름) + 시나리오(E06~E18, D-09·D-11·F-03-05) + 불변식(I1~I10). `SEED=42` |
| `npm test` | `src/**/*.test.ts` | 함수별 단위 테스트 (`node --test`). 이름 모양 6순서 × 8 × 7 표기 다시 읽기(D-42·D-43)도 여기 |
| `npx tsc --noEmit -p .` | — | 타입 |

스크립트는 TypeScript이고 Node 22.18 이상이 그대로 실행한다 (추가 설치 없음). 분석 함수는 `src/analysis/`에서 직접 불러온다.

## 0. 시작 전에
| 확인 | 어떻게 |
|---|---|
| 최신 코드 | `git pull` |
| 분석 함수 | `analyze`(`analyze.ts`), `parseName`(`baseName.ts`), `findDuplicates`·`sameBytes`(`duplicate.ts`), `rename`·`formatVersion`·`formatDate`(`rename.ts`), `acceptFiles`·`toInputFiles`·`loadSamples`(`upload.ts`), `unzipFiles`(`unzip.ts`), `makeDownload`·`zipName`(`zip.ts`), `readDocMeta`(`metadata.ts`). 입력 타입 `InputFile` |
| 결정 상태 | D-19·D-21·D-22가 "보류"면 메타데이터 판정 케이스(M01~M04)는 SKIP. D-18은 확정이라 중복 케이스는 SKIP 없이 검사 |
| 의존성 | `node_modules`가 없으면 `npm install` |

공통 규칙
- **원본을 덮어쓰지 않는다.** `manifest.json`·`expected.json`·demo·edge 파일 목록은 바꾸기 전에 묻는다
- **가명·예시 데이터만.** 문서 안 작성자 이름까지 가명 (D-16)
- **기대 결과는 사람이 CLAUDE.md 규칙 표로 적는다. 분석 코드로 계산하지 않는다.** 같은 버그가 코드와 기대값에 같이 들어가면 테스트가 통과해 버린다
- **수정 날짜는 manifest 값.** git은 수정 날짜를 저장하지 않는다 (D-14)
- **틀려도 바로 고치지 않는다.** 원인과 고칠 방법을 설명하고 승인받은 뒤 고친다

## 1. 규칙 — `rules/version-rules.json`
키워드·점수·패턴은 코드에 직접 쓰지 않고 이 파일에서 읽는다. CLAUDE.md "버전 판정 규칙"을 옮긴 것이고 CLAUDE.md가 기준이다.

| 키 | 내용 | 결정 |
|---|---|---|
| `keywords` | 진짜최종·찐최종 40 / 최종수정 30 / 최종·final·완성·제출 20 / 수정 10. "본"이 붙어도 같은 점수(수정본·최종본…). "진짜"·"본" 단독은 키워드 아님 | D-01, D-26 |
| `copyMarks` | 이름 끝의 `(1)`, `_1`(1~2자리), `복사본`, `- 복사본`, `copy`. 버전으로 세지 않음 | D-02 |
| `dates` | `11월20일`·`11월 20일`·`2026년 11월 20일`(맨 앞), `2026-11-20`, `20261120`, `1120`, `11.20`. 월 1~12·일 1~31일 때만 날짜 | D-03, D-45 |
| `version` | `v2`·`V2`·`ver2` (대소문자 무시, 앞에 영문자가 붙으면 아님: `server3`). `v1.2`는 v1 | D-28 |
| `separators` | 공백·`_`·`-`·괄호 | 기본 이름 5단계 |

규칙 파일 밖에 있는 값
| 값 | 위치 |
|---|---|
| 판정 순서(버전 → 파일명 날짜 → 키워드 → 수정 날짜), 1위 동점·2위 이하 동점 | `analyze.ts` `rank`, `decidingCriterion` |
| 추천 이유 첫 줄 문구 틀 / 자세한 설명 | `analyze.ts` `reasonText` / `reasonDetail` (D-37, 검사는 첫 줄만) |
| 20MB, 같은 파일 판정 | `upload.ts` `MAX_SIZE`, `fileKey` |
| zip 100MB, CP949 이름 | `unzip.ts` `ZIP_MAX`, `decodeName` (D-39) |
| 새 이름 칸 순서·버전 표기 8개·날짜 표기 7개, 충돌 `_2`, 금지 문자 `_` | `rename.ts` `DEFAULT_PATTERN`, `VERSION_FORMATS`, `DATE_FORMATS` (D-42, D-43) |
| 내려받을 zip 이름 | `zip.ts` `zipName` |

**보여주기**: 위 표 모양으로 지금 값을 보여 준다.
**검사하기**: `npm run qa`의 "규칙" 단계 (점수가 CLAUDE.md와 같은지, 정규식이 컴파일되는지). 정규식은 JavaScript 문법, `u` 플래그.

**고치기** — 규칙을 바꾸는 것은 CLAUDE.md를 바꾸는 것이다.
1. 바꾸려는 값이 CLAUDE.md와 다르면 멈추고 알린다
2. 확정되면 함께 고친다: `rules/version-rules.json`, CLAUDE.md의 표·결정 사항(새 D-xx는 "추천안"), `scripts/qa.ts`의 규칙 대조 값과 단위 표(새 예시 1개 이상)
3. 키워드: 기존 키워드를 품는지("완전최종" ⊃ "최종"), 흔한 단어와 겹치는지, 영문 대소문자
4. 날짜·버전 표기: **이름 모양(D-43) 표기를 다시 읽을 수 있는지** `npm test`의 `rename.test.ts`로 확인. 표기를 더하면 그 테스트 목록에도 넣는다
5. 소개 화면 판단 기준 칩(`app/Intro.tsx`의 `CLUES`)에 쓴 예시가 여전히 읽히는지 (`/ux-writing` 3절)
6. `npm run qa` → 3절 빠른 확인 → 기대 결과가 바뀌면 `expected.json`을 사람이 고친다
7. 커밋 예: `F-02-03 키워드 '완전최종' 40점 추가` (`/ship`)

### manifest.json · expected.json
- `manifest.json`: `"demo/파일명": { "lastModified": "2026-11-20T23:40:00+09:00", "author": "가명", … }`. 키 순서 = 목록 순서
- `expected.json`: `scenarios[]`. 시나리오마다 한 번에 올린 파일 묶음(batch 1), `files` 순서 = 목록 순서
  - 파일: `path`, `baseName`, `duplicateOf`, `newName`(`null` = 중복 제외 또는 아직 안 고른 확인 필요)
  - 시나리오: `groups[]`(`baseName`, `status`, `latest`, `reason`), `singles`, `summary`, `blockedGroups`. 적지 않은 칸은 검사하지 않음

## 3. 빠른 확인 — 기능 하나 고친 직후
분석·이름 변경·업로드 코드를 고쳤으면 반드시 한다 (CLAUDE.md 작업 규칙). 1~2분.
```bash
npm run check && npm test && npx tsc --noEmit -p .
```
1. 예시 파일이 없다고 나오면 `npm run samples`부터
2. 분석 코드에서 아래를 찾아 보고한다
   ```bash
   grep -rnE "crypto\.subtle|document\.|window\." src/analysis
   ```
   - 키워드·점수가 코드에 직접 있음 → 규칙 파일에서 읽어야 함
   - `document`·`window` → 화면 코드와 섞지 않음
   - `crypto.subtle` → http 배포 주소에서 안 됨. 크기가 같은 파일끼리 바이트 직접 비교 (D-17)
3. 비교 규칙 (`check-result.ts`가 이렇게 한다): `expected.json`에 적힌 칸만, 추천 이유는 첫 줄을 글자 그대로, 새 이름 날짜는 실행 PC 시간대(KST) 기준
4. 결과 표와 브라우저에서 볼 방법 한 줄 (예: "`/start` → [체험하기] → [분석하기] → 보고서 칩 → 중복 배지")

## 4. 전체 QA
순서: 3절 빠른 확인 → `npm run qa` → `npm run build` → 화면 → http → 보고서
```bash
npm run qa              # seed 42
SEED=7 npm run qa       # 다른 무작위 세트
```
FAIL이 하나라도 있으면 종료 코드 1. PASS가 아닌 것만 보여 주고 마지막에 단계별 개수.

### 4-1. 시나리오 (`scripts/qa.ts`)
파일을 디스크에 만들지 않고 `InputFile`(`name`, `size`, `lastModified`, `order`, `batch`, `bytes`)을 메모리에서 만든다. 중복은 `bytes`를 같게, "이름 같고 내용 다른" 파일은 `bytes`를 다르게, 따로 올린 것은 `batch`를 다르게. 새 경우는 시나리오 블록을 하나 더하고 이름 앞에 케이스 ID·기능 ID.

| ID | 확인할 것 | 관련 |
|---|---|---|
| E01~E05 | edge 5개 (`npm run check`가 실제 파일로) | D-01~D-05, D-08 |
| E06 | v2가 '진짜최종'보다 우선 (기준 1 > 3) | F-02-03 |
| E07 · E08 | `20261119` < `2026-11-20`, `1120` > `1119` | F-02-03, D-03 |
| E09 · E10 · E11 | `VER3`·`FINAL` 대소문자 무시, `찐최종` 40점, `진짜` 단독은 키워드 아님 | D-01 |
| E12 · E13 | 복사본 표시 4종 한 그룹, `_123`(3자리)은 복사본 표시 아님 | D-02 |
| E14 · E15 · E15b | 이름 같고 내용 다르면 중복 아님, 그룹이 달라도 중복, 따로 올리면 나중 쪽이 중복(복사본 표시보다 우선) | F-02-06, D-04 |
| E16 · F-01-01 | 20MB 초과는 빼고(M-03) 딱 20MB는 받음, 같은 파일 다시 올림(M-04) | F-01-01, F-01-04 |
| E17 · E18 | 확장자 없음, 다 지워서 빈 이름 → 복사본 표시만 지운 이름 | F-01-04, D-27 |
| D-09 · D-11 · F-03-05 | 직접 고른 파일이 가장 큰 번호, [최신 파일만]에 단독 포함, 금지 문자 `_`·겹침 `_2` | F-02-05, F-03 |
| M01~M04 | 메타데이터 판정 4줄 — D-19 허용 전에는 SKIP | D-21, D-22 |

### 4-3. 불변식 — 무작위 파일명
seed로 무작위 세트 300개(기본 이름 + 서로 다른 꾸밈 2개 + 복사본 표시, 15%는 바이트 같은 사본)를 만들어 확인한다.
- I1 새 이름 형식·금지 문자 없음 · I2 그룹마다 번호 1..k 한 번씩 · I3 최신 후보가 가장 큰 번호 · I4 확인 필요는 선택 없음
- I5 입력 순서를 섞어도 그룹·최신 후보 같음(1위 동점, 바이트 같은 파일은 제외) · I6 두 번 돌려도 같음
- I7 새 이름끼리 안 겹침 · I8 꾸밈만 다르면 같은 그룹 · I9 중복은 번호·내려받기 없음 · I10 추천 이유가 문구 틀 중 하나

실패하면 파일을 하나씩 빼며 **가장 작은 실패 세트**로 줄이고, 시나리오로 추가하자고 제안한다 (기대 결과는 사람이). seed를 보고서에 적는다. 생성기가 비현실적인 이름(날짜 2개 등)을 만든 탓이면 생성기를 고친다.

### 4-4. 화면
`npm run dev`로 띄워 브라우저로 본다. 폭별 모양은 `/screen-capture`, 디자인 기준은 `/design-review`, 문구는 `/ux-writing`.
수정 날짜가 manifest 값이 되도록 파일은 페이지 안에서 `File`로 만들어 넣는다:
```js
const dt = new DataTransfer();
for (const f of files) dt.items.add(new File([new Uint8Array(f.bytes)], f.name, { lastModified: f.lastModified }));
const input = document.querySelector('input[type=file]');
input.files = dt.files; input.dispatchEvent(new Event('change', { bubbles: true }));
// 끌어다 놓기(F-01-02): 드롭 영역에 new DragEvent('drop', { dataTransfer: dt })
```

### 4-5. http 주소 (꼭 한다)
배포 주소는 https가 아니라 `crypto.subtle`이 없다. localhost는 안전한 주소로 취급되므로 통과해도 믿지 않는다.
- `npm run dev -- -H 0.0.0.0`으로 띄우고 `http://<사설 IP>:3000/start`에서 `window.isSecureContext === false`부터 확인
- 그 상태에서 중복 케이스(edge 자료_v2, E14, E15)를 다시 본다
- 배포 주소(`/file-version/start`)에서도 같은 검사. 네트워크 기록에 파일을 서버로 보내는 요청이 없는지 (D-17)

## 5. 판정과 보고
| 결과 | 뜻 |
|---|---|
| PASS | 기대 결과와 같음 |
| FAIL | 다름. 실제·기대 값과 기능 ID |
| SKIP | 조건이 안 됨 (D-19 보류 등). 이유 |
| 확인 필요 | 문서만으로 정답을 정할 수 없음. 팀이 정할 질문 한 줄 |

- FAIL이면 원인과 고칠 방법을 먼저 설명하고 승인받은 뒤 고친다. 고친 뒤 다시 돌린다
- 기대 결과가 CLAUDE.md와 다르다고 보이면 코드를 맞추지 말고 멈추고 알린다
- "보류" 결정은 명세서대로 동작하는 것을 정답으로 본다
- 있으면 좋은 기능 작업 중 필수 기능(상)이 깨지면 직전 커밋으로 되돌리자고 제안한다

보고서는 `output/qa-report-YYYYMMDD-HHMM.md`(빠른 확인은 `output/check-result-YYYYMMDD-HHMM.md`)에 새 파일로, 결론을 맨 위에:
```markdown
# QA 결과 — 2026-11-21 14:30
**결론: FAIL 1 · PASS 40 · SKIP 4 · 확인 필요 2** — 배포 전에 http 중복 판별부터

| 단계 | PASS | FAIL | SKIP | 확인 필요 |
|---|---|---|---|---|
| 규칙 · 빠른 확인 · 단위 · 시나리오 · 불변식 · 화면 · http | | | | |

## FAIL
| 케이스 | 기능 | 기대 | 실제 | 추정 원인 |

## 확인 필요 (팀이 정할 것)
| 케이스 | 질문 |

## 실행 정보
seed · 커밋 해시 · 실행 명령 · Node·브라우저 버전
```
마지막에 변경한 파일 표와 사용한 "추천안"·"보류" 결정 ID. 커밋은 `/ship` (예: `F-01-03 예시 파일과 manifest 추가`, `QA E19 … 추가`).
