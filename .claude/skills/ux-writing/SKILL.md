# 화면 문구 다듬기

기준: `DESIGN.md` 9장 말투, `CLAUDE.md`의 안내 메시지 표(M-01~M-12, 문구 그대로), 버튼·배지 이름, `public/samples/expected.json`.

## 1. 문구 모으기
- 대상 파일의 JSX 글자, `aria-label`, `title`, 배열 상수(`STEPS`, `CLUES`, `BEFORE`, `AFTER`, `NAMES`)를 모두 모은다
- 안내 메시지(M-xx)는 **고치지 않는다.** CLAUDE.md 문구와 글자 하나까지 같은지만 본다

## 2. 검사표
| 검사 | 고치는 방향 | 예 |
|---|---|---|
| ~요체 | "~합니다", "~함" → ~요 (표·배지의 짧은 이름은 명사) | "처리합니다" → "다뤄요" |
| 쉬운 말 | 개발 용어 빼기 | "메타데이터" → "문서 안 기록", "전송" → "보내기" |
| 과장·단정 | 추천은 후보 | "바로 알려 드려요" → "찾아 드려요", "최신 파일" → "최신으로 보이는 파일" |
| 사실과 다른 약속 | 실제 동작과 맞추기 | "폴더째 넣어도 돼요" → "zip 파일도 그대로 올릴 수 있어요" (폴더는 M-07) |
| 버튼 이름 | 화면에 있는 이름 그대로 | "[예시 파일로 해보기]" → "[체험하기]" (D-36) |
| 판단 설명 | 판정 규칙과 같게 | 수정 날짜는 이름 속 단서가 아님, 중복은 이름이 아니라 내용으로 판단 |
| 어색한 직역 | 사람이 하는 말로 | "어떻게 동작하나요?" → "무슨 원리인가요?" |
| 높임 일관 | "~드려요"(서비스가 해 줌), "~주세요"(사용자에게 부탁) | "보여 줘요" → "보여 드려요" |
| 문장 길이 | 한 문장에 한 뜻. 두 문장 설명은 문장마다 한 줄 | |

## 3. 예시 값 맞추기 (소개 화면)
`app/IntroDemo.tsx`와 `app/Intro.tsx`의 예시는 손으로 적은 값이라 규칙·예시 파일이 바뀌면 어긋난다.

| 화면 값 | 비교할 곳 |
|---|---|
| "정리 전" 24개 이름 | `public/samples/demo/` 파일 이름 (24개, D-34) |
| 묶음(`group`)과 최신·중복 표시(`mark`) | `expected.json` "시연용 예시 24개"의 `groups[].latest`, `files[].duplicateOf`, `singles` |
| "정리 후" 새 이름 | 그 묶음 최신 파일의 `newName` (두 자리 번호 `_v04_`, D-33) |
| 개수 ("파일 24개", "문서 10개", "N개") | `files` 수, 그룹 7 + 단독 3 |
| 판단 기준 칩 (`v2`, `ver4`, `11월20일` …) | `rules/version-rules.json`이 읽는 표기만 |

- 다르면 화면 값을 expected.json에 맞춘다. expected.json 자체가 틀렸다고 보이면 고치지 말고 `/QA`로 넘긴다
